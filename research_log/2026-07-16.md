# TSRT Weekly Research Log

## Period

Week of July 2026

## Objective

This week focused on building the teacher-forcing dataset used to supervise retrieval-state learning in the TSRT (Task-State Retrieval Transformer) architecture.

The goal is to generate reasoning traces from a stronger teacher model and use them as supervision signals during TSRT training.

---

## Teacher Label Generation Pipeline

### Teacher Model

A pretrained Qwen3-8B model was selected as the teacher model.

Configuration:

- Model: Qwen/Qwen3-8B
- Quantization: 4-bit NF4 (BitsAndBytes)
- Compute dtype: bfloat16
- Batch size: 32
- Max input length: 2048
- Max generated tokens: 256

Using 4-bit quantization significantly reduced GPU memory requirements while maintaining reasoning quality.

---

### Prompt Construction

For each HotpotQA sample, only supporting documents were provided to the teacher model.

The prompt contains:

- Question
- Ground-truth answer
- Supporting fact annotations
- Positive evidence documents

The teacher is instructed to:

- Produce concise evidence-based reasoning
- Refer to document titles rather than document order
- Avoid unnecessary explanations

Prompt structure:

Question

Ground Truth Answer

Supporting Facts

Evidence Documents

Task:
Generate a concise evidence-based reasoning.

Reasoning:

This setup encourages generation of explicit multi-hop reasoning chains grounded in the supporting documents.

---

### Generation Control

A custom stopping criterion was implemented.

Generation automatically stops when the model begins emitting:

- "Answer"

This prevents the teacher from generating duplicate answer sections and keeps outputs focused on reasoning traces.

After generation:

- Any trailing answer section is removed
- Ground-truth answer is appended manually

Final format:

Reasoning ...

Answer: <ground truth answer>

This guarantees answer correctness while preserving teacher reasoning.

## Teacher Dataset Construction

### Source Dataset

HotpotQA Distractor setting was used.

Original splits:

| Split      | Samples |
| ---------- | ------: |
| Train      |  90,447 |
| Validation |   7,405 |

Each original sample contains:

- Question
- Answer
- Supporting facts
- Context documents

---

### Teacher Annotation Process

For every sample:

1. Generate teacher reasoning using Qwen3-8B
2. Copy original sample
3. Add a new field:

teacher_answer

The resulting schema becomes:

- id
- question
- answer
- type
- level
- supporting_facts
- context
- teacher_answer

No original information is removed.

---

### Chunk-Based Processing

Generating labels for the full dataset requires many hours of inference.

To avoid losing progress:

- Samples are periodically written to disk
- Each chunk contains 1,000 examples
- JSONL format is used

Example:

train_00000.jsonl
train_00001.jsonl
...
validation_00000.jsonl

Benefits:

- Crash recovery
- Incremental progress tracking
- Easier debugging
- Lower memory usage

---

## Hugging Face Dataset Release

After all chunks are generated:

1. JSONL chunks are loaded
2. Converted into Hugging Face Dataset objects
3. Combined into a DatasetDict
4. Uploaded to Hugging Face Hub

Repository:

TSRT-HotpotQA-Teacher

Dataset structure:

train
validation

Additional field:

teacher_answer

This dataset serves as the supervision source for TSRT retrieval-state learning and reasoning-aware training.

---

## Motivation for Teacher Forcing

Traditional retrieval systems only learn:

Question → Retrieved Documents → Answer

They do not explicitly learn:

- When retrieval should happen
- Why retrieval is necessary
- How evidence contributes to reasoning

The teacher-forcing dataset introduces intermediate reasoning supervision.

TSRT can therefore learn:

- Retrieval decisions
- Evidence utilization
- Multi-hop reasoning behavior

rather than relying solely on answer-level supervision.
